Web Dev 101

Frontend, backend, and the tools between

Every site splits into two jobs: what runs in the visitor's browser, and what runs on a server they never see directly.

Frontend

The frontend is everything rendered client-side — the HTML that structures a page, the CSS that styles it, and the JavaScript that makes it interactive. The login form on this site is frontend work: it's just a page waiting for input, with no idea yet whether the email you type is valid.

Common frontend tools: HTML, CSS, JavaScript, and frameworks like React or Vue for larger apps.

Backend

The backend is the part that runs somewhere else — a server that stores data, checks credentials, and decides what to send back. On this site, that's Appwrite: it holds accounts, issues the magic link in your email, and confirms whether a session is valid before this page is allowed to load.

Common backend tools: databases like PostgreSQL or MongoDB, backend-as-a-service platforms like Appwrite or Supabase, and server languages like Node.js, Python, or PHP.

How they meet

The two sides talk over the network. Your browser sends a request — "log this email in," "show me the homepage" — and the backend answers with data or a redirect. The login flow on this site is a small, complete example: frontend collects an email, backend verifies a click on a magic link, and every protected page checks with the backend before it renders.
